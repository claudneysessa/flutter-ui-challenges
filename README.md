134 app screens rebuilt in Flutter, browsable from a single app that also shows you the
source of whichever screen you are looking at.
Consider contributing if you find this project helpful.

**[Open the live demo](https://claudneysessa.github.io/flutter-ui-challenges/)** — the Flutter
web build of this fork, published from the `gh-pages` branch. It is the same code as `master`,
compiled for the browser; the app was designed for phones, so a narrow window looks best.

> **This is a maintained fork.** The original project by
> [Damodar Lohani](https://github.com/lohanidamodar/flutter_ui_challenges) was archived by
> its author in 2024 and no longer compiled with current toolchains. This fork brings it

## What changed in the 2026 revival

The project had been untouched since September 2021. `flutter analyze` reported 208 errors
before a single line could be compiled, and no platform built. High level summary — see
[CHANGELOG.md](CHANGELOG.md) for the full list and
[docs/MIGRATION-ANALYSIS.md](docs/MIGRATION-ANALYSIS.md) for the analysis behind it:

- **Framework API removals**, five years of them: the legacy Material buttons at 103 call
  sites, the 2018 `TextTheme` names, `ThemeData.accentColor` and friends,
  `BottomNavigationBarItem.title`, the `Overflow` enum, `Scaffold`-based snack bars.
- **Dependencies** all moved to current releases, four of them with breaking APIs.
  `share` was discontinued and became `share_plus`; `flare_flutter` was archived and could
  not be saved, taking the Intro 5 demo with it.
- **Every image is now in the repository.** They used to load from the original author's
  Firebase Storage bucket, which Google withdrew from its no-cost plan — all 86 URLs
  return HTTP 402 — and from third-party hosts, two of which have since started returning
  403 and one of which no longer resolves. The app renders identically with no network.
- **Android toolchain rebuilt** on the current Flutter template: Gradle 9.1, AGP 9.0.1,
  Kotlin 2.3, Kotlin DSL, Java 17, a namespace and the `INTERNET` permission. The Windows
  and Linux runners were regenerated as CMake projects; `flutter build windows` previously
  reported "No Windows desktop project configured".
- **Test suite added** (144 tests, building every demo in the catalogue), which found
  several long-standing bugs along the way: three widgets calling `super.dispose()` before
  disposing their controllers, a keep-alive that never called `super.build()` and so was
  not keeping anything alive, a quiz score printed as a raw double division, and three
  demos pointing at source files that do not exist.

Supported platforms: **Android, iOS, Web, Windows, Linux and macOS**. Android, web and
Windows were built and verified; iOS and macOS could not be built on the machine used for
the migration (Windows) — verify them on macOS before shipping.

## Getting Started

Requirements: Flutter 3.38.1 or newer (validated on 3.44.6), Dart 3.10+, JDK 17+ and the
Android SDK for Android builds.

```bash
flutter pub get
flutter analyze
flutter test
flutter run                      # or: flutter run -d chrome / -d windows
```

Regenerating the screenshots in this README, against a connected device:

```bash
flutter drive \
  --driver=test_driver/screenshot_driver.dart \
  --target=integration_test/screenshots_test.dart \
  -d DEVICE_ID
```

For help getting started with Flutter, view online
[documentation](https://flutter.dev/).
